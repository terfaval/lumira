# Lumira Reflective Thread Model v0

## Purpose

This document defines the conceptual thread model of Lumira’s Reflective Space.

It describes:

* what reflective threads are,
* how threads emerge,
* how they evolve over time,
* how they relate to highlights, motifs, and responses,
* how resurfacing and revisitation function,
* and how Lumira avoids collapsing into chatbot, workflow, or task-management interaction patterns.

This document is:

* conceptual,
* interaction-oriented,
* orchestration-aware,
* implementation-agnostic.

It is NOT:

* a finalized schema,
* a persistence implementation,
* or an API contract.

---

# 1. Core philosophy

Reflective threads are:

# reflective trajectories.

They are NOT:

* conversations,
* questionnaires,
* workflows,
* task chains,
* or card sequences.

A reflective thread represents:

# sustained attention around a reflective center.

This center may evolve over time.

---

# 2. Thread identity

A thread is defined by:

# reflective continuity,

not:

# rigid structural hierarchy.

The user should experience a thread as:

* “this is the same line of reflection”
  rather than:
* “this is the next step.”

---

# 3. Thread centers

Every thread has:

# a current reflective center.

The center may be:

* a highlight,
* a motif,
* a scene,
* a relationship,
* an unresolved tension,
* a reflective opening,
* an emotional structure,
* a prior response,
* or a continuity pattern.

The center may shift over time.

---

# 4. Thread emergence

Threads may emerge from:

| Origin type         | Example                                  |
| ------------------- | ---------------------------------------- |
| Highlight           | user marks emotionally dense moment      |
| Glossary motif      | recurring symbol resurfaces              |
| Reflective opening  | AI surfaces unresolved possibility       |
| Reflective response | user deepens a previous answer           |
| Scene fragment      | specific dream transition becomes active |
| Emotional cluster   | repeated emotional tone emerges          |
| Continuity signal   | dormant pattern reactivates              |
| Manual initiation   | user starts new reflection               |

---

# 5. Thread attachment model

Threads may attach to:

* highlights,
* glossary motifs,
* dream excerpts,
* reflective openings,
* reflective responses,
* continuity signals,
* or the dream-space itself.

Threads are:

# many-to-many reflective structures.

A thread is not limited to:

* one card,
* one prompt,
* or one dream fragment.

---

# 6. Reflective gravity model

Threads behave like:

# reflective gravity fields.

Meaning:

* related reflective material gradually gathers around them,
* continuity strengthens over time,
* and reflective density may increase.

Examples:

* multiple highlights converge,
* recurring motifs cluster,
* several responses orbit similar tension,
* revisitations deepen the same unresolved structure.

The user should feel:

* continuity,
* not progression.

---

# 7. Thread lifecycle states

Threads may exist in the following states:

| State     | Meaning                            |
| --------- | ---------------------------------- |
| Open      | actively reflective                |
| Answered  | meaningful response exists         |
| Deferred  | intentionally postponed            |
| Dormant   | inactive but continuity-relevant   |
| Revisited | reactivated after prior engagement |
| Dismissed | intentionally suppressed           |

---

# 8. Open state

## Open Thread

Represents:

* active reflective attention,
* unresolved engagement,
* or current reflective gravity.

Characteristics:

* visible in Orientation Layer
* available in Deep Reflection
* may surface reflective openings
* may receive new responses

Open threads should feel:

* alive,
* available,
* but not demanding.

---

# 9. Answered state

## Answered Thread

Represents:

* meaningful reflective engagement already occurred.

Important:
Answered does NOT mean:

# complete.

A thread may:

* remain emotionally active,
* later deepen,
* or become revisited.

Characteristics:

* response continuity preserved
* thread remains searchable/revisitable
* may re-enter Open or Revisited states later

---

# 10. Deferred state

## Deferred Thread

Represents:

# “not now.”

This is:

* intentional postponement,
* not abandonment.

Deferred threads:

* reduce foreground reflective demand,
* but remain continuity-aware.

Characteristics:

* hidden from active focus
* lightly present in Orientation Layer
* resurfacable later

---

# 11. Dormant state

## Dormant Thread

Represents:

* inactive reflective continuity.

Dormancy may occur:

* naturally,
* after long inactivity,
* or after reflective stabilization.

Dormant threads:

* should not compete for attention,
* but remain part of reflective topology.

Characteristics:

* background continuity role
* low resurfacing priority
* historical reflective context

---

# 12. Revisited state

## Revisited Thread

Represents:

# renewed reflective activation.

Revisitation may occur because:

* motif recurs,
* user returns,
* emotional relevance increases,
* new dream connects,
* or unresolved tension resurfaces.

Characteristics:

* stronger reflective weight
* continuity emphasis
* possible resurfacing priority increase

Revisited threads often represent:

# important reflective continuity.

---

# 13. Dismissed state

## Dismissed Thread

Represents:

* explicit reflective rejection,
* or intentional removal from active space.

Dismissal is:

* user-controlled,
* not AI-controlled.

Dismissed threads:

* should stop resurfacing aggressively,
* unless explicitly restored later.

Important:
Dismissal does NOT imply:

* invalidity,
* failure,
* or incorrectness.

Only:

# “this is not meaningful right now.”

---

# 14. Thread resurfacing philosophy

Threads may resurface when:

* related motifs recur,
* reflective density increases,
* user revisits connected material,
* continuity signals strengthen,
* or unresolved structures reactivate.

Resurfacing should feel:

* gentle,
* contextual,
* and rare.

Never:

* notification-driven,
* urgent,
* or productivity-oriented.

---

# 15. Reflective saturation control

Not all active threads should compete equally.

The system should continuously distinguish between:

* foreground reflective structures
* background reflective structures

This preserves:

# reflective quietness.

---

## Foreground thread examples

* recently revisited
* emotionally dense
* user-confirmed importance
* continuity-active
* currently deepened

---

## Background thread examples

* historical
* lightly unresolved
* dormant
* low-relevance continuity
* weakly connected

---

# 16. AI participation model

AI does not:

* own threads,
* control thread direction,
* or enforce continuation.

AI participates by:

* surfacing openings,
* noticing continuity,
* suggesting unresolved areas,
* or gently deepening reflective attention.

AI behavior must remain:

* invitational,
* not directive.

---

# 17. Reflective openings inside threads

Reflective openings may appear:

* inside active threads,
* near relevant highlights,
* during revisitation,
* or after reflective responses.

Openings should behave as:

# reflective possibilities.

Not:

# next-step instructions.

---

# 18. Thread navigation philosophy

Users navigate:

# through reflective continuity,

not:

# through sequential routes.

Thread navigation may include:

* returning to prior reflective states,
* branching sideways,
* deepening existing centers,
* or reconnecting dormant material.

The user should feel:

* free movement within reflective topology.

---

# 19. Branching model

Threads may:

* branch,
* merge,
* overlap,
* or loosely connect.

Important:
Branching should NOT resemble:

* decision trees,
* dialogue trees,
* or workflow branching.

Instead:
branching behaves like:

# associative reflective movement.

---

# 20. Relationship to legacy systems

| Legacy system      | Future thread interpretation     |
| ------------------ | -------------------------------- |
| Work cards         | localized reflective activations |
| dream_answers      | reflective responses             |
| work_versions      | historical thread states         |
| direction flow     | attention weighting              |
| question sequences | reflective openings              |

Long-term:
the old card system may dissolve into:

# thread-centered reflective engagement.

---

# 21. Thread visibility model

Thread visibility depends on:

* reflective weight,
* continuity activity,
* user confirmation,
* revisitation,
* and current focus context.

Not every thread should remain:

* equally visible,
* equally active,
* or equally surfaced.

---

# 22. Mobile thread behavior

On mobile:

* thread focus should narrow aggressively,
* surrounding reflective density should reduce,
* and continuity context should remain lightly accessible.

Thread transitions should feel:

* calm,
* fluid,
* and non-fragmenting.

---

# 23. Future evolution direction

Threads may later support:

* cross-dream continuity,
* motif-linked reflective maps,
* dormant resurfacing systems,
* reflective topology visualization,
* continuity-weighted surfacing,
* and associative reflective exploration.

However:
the system must always preserve:

# contemplative pacing over information density.

---

# 24. Final principle

Reflective threads should not feel like:

* software workflows.

They should feel like:

# living lines of attention that can be returned to over time.
