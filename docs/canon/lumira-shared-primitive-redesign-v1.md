# Lumira Shared Primitive Redesign v1

## Status

Foundational redesign specification for Lumira’s shared UI primitives.

This document defines:

* visual primitives
* interaction primitives
* surface behaviors
* density rules
* motion behaviors
* reflective interaction materials

This document is:

* implementation-guiding
* system-level
* reflective-runtime-aware

This document is NOT:

* route-specific screen design
* token implementation
* CSS specification
* component code

---

# 1. Purpose

Lumira’s reflective runtime architecture and interaction philosophy now require a new primitive layer.

The previous primitive system emerged from:

* cinematic glassmorphism
* dashboard-oriented organization
* floating card systems
* productivity interaction language
* AI-product aesthetics

The new primitive system must support:

# reflective attention environments.

The goal:

* reduce emotional pressure
* preserve continuity awareness
* support layered reflection
* maintain optionality
* embody reflective pacing
* materialize attentional calmness

---

# 2. Primitive philosophy

## 2.1 Primitives are attentional structures

Shared primitives are not decorative UI components.

They define:

* what becomes foreground
* what becomes ambient
* what remains quiet
* what requests attention
* what recedes into continuity

Every primitive therefore carries:

* attentional weight
* emotional energy
* continuity salience
* pacing implications

---

## 2.2 Reflective environments are not dashboards

The primitive system must avoid:

* simultaneous foreground competition
* utility-first interaction
* card-grid ontology
* analytics aesthetics
* productivity pacing

The interface should feel:

# inhabitable,

not:

# operated.

---

## 2.3 Calmness is structural

Calmness does not come from:

* fewer features
* empty layouts
* aesthetic minimalism alone

Calmness emerges from:

* density control
* continuity layering
* pacing
* optionality
* restrained interaction energy
* quiet hierarchy

Primitives must therefore:

# regulate attention.

---

# 3. Core primitive ontology

Lumira should reduce the UI to a small number of primitive categories.

---

# 4. Surface primitives

## 4.1 Reflective Surface

Primary reflective substrate.

Used for:

* dream text
* reflective writing
* deep reflection
* thread focus
* reflective responses

Characteristics:

* matte
* grounded
* text-first
* minimal containment
* soft tonal separation
* no theatrical elevation

Should feel:

# stable enough to think inside.

Avoid:

* glass effects
* hover emphasis
* floating illusion
* visual spectacle

---

## 4.2 Ambient Surface

Secondary continuity/orientation substrate.

Used for:

* orientation layer
* continuity cues
* reflective openings
* glossary continuity
* resurfacing hints
* unresolved adjacency

Characteristics:

* visually recessive
* lighter hierarchy
* expandable
* breathable
* partially demoted

Purpose:

# gentle awareness,

not:

# demand.

---

## 4.3 Utility Surface

Explicit operational UI.

Used for:

* settings
* filters
* drawers
* menus
* navigation
* destructive actions

Characteristics:

* compact
* clear
* structurally explicit
* emotionally neutral

Utility surfaces must remain:

# visually secondary

inside reflective contexts.

---

## 4.4 Transitional Surface

Temporary attentional bridge.

Used for:

* overlays
* inline expansion
* thread focus transition
* glossary expansion
* continuity reveal
* composer invocation

Characteristics:

* temporary
* low-pressure
* softly bounded
* context-preserving

Transitions should feel:

# continuous,

not:

# modal and disruptive.

---

# 5. Interaction primitives

## 5.1 Reflective Expansion

Primary reflective interaction pattern.

Examples:

* expanding a highlight
* opening a thread
* revealing glossary continuity
* opening a reflective invitation

Expansion should feel:

* invitational
* soft
* reversible
* non-committal

Avoid:

* dramatic reveal
* aggressive transitions
* “open task” feeling

---

## 5.2 Quiet Persistence

Important continuity should remain available without demanding attention.

Examples:

* dormant thread indicators
* unresolved motifs
* weak continuity signals
* revisitable reflections

Persistence should feel:

# patient.

Not:

# waiting for completion.

---

## 5.3 Contextual Invocation

Actions should emerge from context.

Examples:

* note writing from highlight selection
* reflective response from invitation
* glossary exploration from motif
* thread continuation from reflective state

Avoid:

* global action overload
* persistent control surfaces
* toolbar-heavy interaction

---

## 5.4 Reflective Narrowing

Deep reflection should reduce visible complexity.

When entering deep reflection:

* peripheral continuity softens
* unresolved density suppresses
* adjacent threads demote
* orientation becomes quieter

Goal:

# attentional narrowing,

not:

# workflow zoom-in.

---

# 6. Typography primitives

## 6.1 Reflective Body

Primary reading/writing typography.

Characteristics:

* warm
* breathable
* moderate line height
* low visual fatigue
* emotionally calm

Should support:

* long reading
* associative thought
* slow reflection

---

## 6.2 Quiet Metadata

Used for:

* timestamps
* recurrence indicators
* continuity references
* thread state labels

Characteristics:

* low dominance
* reduced uppercase
* reduced tracking
* visually softened

Metadata should feel:

# available,

not:

# signaling.

---

## 6.3 Orientation Typography

Used for:

* frame/context
* continuity overviews
* reflective openings
* ambient summaries

Characteristics:

* softer than primary reflection
* less authoritative
* lightly contextual

Avoid:

* “AI explanation” tone
* interpretive certainty
* editorial dominance

---

# 7. Continuity primitives

## 7.1 Reflective Continuity Marker

Used for:

* recurring motifs
* glossary recurrence
* unresolved continuity
* revisitable threads

Markers should:

* orient
* hint
* softly connect

Not:

* assert meaning
* imply hidden knowledge
* dramatize significance

---

## 7.2 Reflective Opening

A temporary reflective invitation.

Not:

* a task
* a mandatory prompt
* a chatbot turn

Characteristics:

* optional
* contextual
* calm
* non-escalating

An opening should feel:

# present,

not:

# demanding.

---

## 7.3 Dormant Continuity

Dormant elements remain:

* accessible
* quiet
* non-urgent

Dormancy is valid.

Dormant primitives must never visually imply:

* incompletion
* failure
* neglect

---

# 8. Motion primitives

## 8.1 Soft Reveal

Preferred reveal pattern.

Use:

* opacity
* tonal shift
* gentle expansion
* contextual emergence

Avoid:

* scaling
* bouncing
* snap transitions
* energetic transforms

---

## 8.2 Quiet Transition

State changes should preserve:

* continuity
* orientation
* emotional stability

Transitions should never feel:

* gamified
* rewarding
* urgent

---

## 8.3 Ambient Motion

Allowed only for:

* atmosphere
* breathing continuity
* soft environmental presence

Ambient motion must remain:

* low-frequency
* low-contrast
* slow
* non-demanding

---

# 9. Density primitives

## 9.1 Foreground Density Budget

Only a small number of elements may simultaneously occupy foreground attention.

Foreground candidates:

* active reflection
* selected thread
* reflective writing
* currently expanded continuity

Everything else should demote.

---

## 9.2 Midground Continuity

Midground continuity remains:

* visible
* quiet
* revisitable
* softly grouped

Purpose:

# orientation without overload.

---

## 9.3 Background Continuity

Background continuity:

* persists structurally
* recedes visually
* avoids emotional demand

Background continuity is:

# atmospheric memory.

---

# 10. Atmospheric primitives

## 10.1 Warm ambient field

Atmosphere should feel:

* warm
* soft
* lightly tactile
* calm
* grounded

Avoid:

* cosmic spectacle
* neural metaphors
* mystical aesthetics
* sci-fi consciousness visuals

---

## 10.2 Instrument restraint

The interface may feel:

* instrument-like
* thoughtful
* quietly structured

But should avoid:

* control panel overload
* decorative machinery
* excessive visual instrumentation

The system should suggest:

# subtle reflective instrumentation,

not:

# analytical machinery.

---

# 11. Primitive anti-patterns

Avoid primitives that imply:

## 11.1 Workflow progression

Examples:

* step cards
* active pipelines
* progress framing
* completion stacks

---

## 11.2 Insight authority

Examples:

* glowing insight blocks
* AI confidence styling
* dramatic reveal hierarchy
* interpretive emphasis

---

## 11.3 Dashboardification

Examples:

* chip flooding
* simultaneous cards
* dense utility clusters
* analytics framing

---

## 11.4 Cinematic drift

Examples:

* deep blur stacks
* glow-heavy atmosphere
* floating glass planes
* theatrical overlays

---

## 11.5 Compulsive continuation

Examples:

* unresolved urgency
* escalation markers
* persistent prompts
* aggressive resurfacing

---

# 12. Shared primitive migration targets

The following existing systems likely require redesign or replacement:

* GlassCardSurface
* glass-panel variants
* hover-lift interactions
* premium elevation shadows
* chip-heavy continuity blocks
* cinematic overlays
* floating action patterns
* dense utility toolbars
* aggressive loading overlays
* high-emphasis metadata systems

---

# 13. Implementation implications

This redesign implies:

* shared primitives should be rebuilt before route redesign
* tokens alone are insufficient
* reflective pacing must constrain component behavior
* surface hierarchy must become explicit
* continuity layering must become systemic
* motion defaults must change globally
* utility UI must demote inside reflective spaces

---

# 14. Recommended implementation order

1. Surface ontology implementation
2. Typography normalization
3. Motion primitive replacement
4. Density budgeting system
5. Atmospheric simplification
6. Shared utility primitive redesign
7. Reflective Space implementation
8. Route-level migration

---

# 15. Final principle

Shared primitives should not feel like:

# reusable UI widgets.

They should feel like:

# reusable attentional conditions inside a reflective environment.
