# Lumira Evolution North Star v0

## 1. Vision and Product Identity

Lumira is a reflective dream cognition companion.

Dreams are treated as privileged reflective material: compressed experiential traces where emotional, relational, and existential continuity often becomes more visible than in ordinary waking narration.

Lumira’s role is not to pronounce meaning, but to support reflective traversal.

- Not anti-interpretive.
- Anti-authoritative interpretation.

Internal cognition may infer and prioritize patterns probabilistically. External interaction must remain user-led, revisable, and ambiguity-preserving.

Conceptual framing:

- Royal-road inspiration: dreams can open access to implicit psychic continuity.
- Companion metaphor: Lumira walks with the user through reflective terrain, it does not dominate the map.
- Contemplative orientation: calm pacing, phenomenological respect, and non-coercive attention.

## 2. Core Reflective Cognition Architecture

Canonical layer model:

1. Dream substrate
2. Observation layer
3. Latent cognition layer
4. Highlights / salience layer
5. Glossary / continuity memory
6. Reflective thread runtime
7. Reflective dialogue layer
8. Attention shaping / orientation layer

Per-layer north-star contract:

- Dream substrate
  - Purpose: canonical source material.
  - Ownership: user-owned text and edits.
  - Visibility: primary and always accessible.
  - Runtime role: source-of-truth anchor for all cognition.
  - User relationship: authorial ownership.
  - Long-term direction: stable foundation across all future domains.
- Observation
  - Purpose: evidence-linked descriptive structuring.
  - Ownership: system-generated from user material.
  - Visibility: mostly internal, selective derivatives surfaced.
  - Runtime role: descriptive substrate for downstream cognition.
  - User relationship: quiet support, never imposed meaning.
  - Long-term direction: richer phenomenological fidelity.
- Latent
  - Purpose: probabilistic internal reflective inference.
  - Ownership: system-generated internal model.
  - Visibility: internal-only in raw form.
  - Runtime role: continuity/tension/priority inference.
  - User relationship: transformed into gentle invitations.
  - Long-term direction: stronger multi-reading continuity cognition.
- Highlights
  - Purpose: user-owned salience marking.
  - Ownership: user-confirmed anchors.
  - Visibility: user-visible and interactive.
  - Runtime role: primary interaction primitive and continuity activator.
  - User relationship: meaning ownership signal.
  - Long-term direction: central reflective navigation substrate.
- Glossary
  - Purpose: personal recurrence memory.
  - Ownership: user-confirmed motif memory.
  - Visibility: contextual and optional.
  - Runtime role: continuity recall and resurfacing support.
  - User relationship: reflective memory companion, not authority.
  - Long-term direction: continuity-aware memory network.
- Reflective threads
  - Purpose: continuity trajectories over time.
  - Ownership: user-led continuity paths with system support.
  - Visibility: user-visible continuity structure.
  - Runtime role: organize openings, responses, notes, resurfacing.
  - User relationship: revisitable lines of reflection.
  - Long-term direction: non-linear reflective topology.
- Reflective dialogue
  - Purpose: safe invitation surface.
  - Ownership: system phrasing constrained by user autonomy.
  - Visibility: user-facing invitations.
  - Runtime role: convert internal cognition to non-coercive openings.
  - User relationship: companionship, not interrogation.
  - Long-term direction: fewer, stronger, context-rich invitations.
- Attention shaping/orientation
  - Purpose: soft reflective weighting.
  - Ownership: user-selectable lenses plus system suggestions.
  - Visibility: secondary orienting context.
  - Runtime role: influence surfacing and pacing, not lock flow.
  - User relationship: optional guidance.
  - Long-term direction: adaptive reflective orientation substrate.

## 3. Observation Layer Evolution

Observation is descriptive cognition.

Observation answers:

- What appears in the dream?

Observation does not answer:

- What does this dream mean?

Evolution direction:

- phenomenological modeling (perspective, embodiment, fragmentation, dream-state quality)
- Hall–Van de Castle-informed social/interaction patterning
- affect and transition modeling
- agency and constraint modeling
- lucidity/metacognitive cue modeling
- evidence-linked extraction discipline

Contract:

- descriptive
- traceable to source evidence
- ambiguity-preserving
- non-authoritative

## 4. Latent Cognition Evolution

Latent cognition is internal probabilistic reflective modeling.

Evolution direction:

- continuity modeling across sessions
- probabilistic hypothesis formation
- emotional prioritization
- unresolved tension modeling
- relational dynamic modeling
- narrative identity trajectory inference
- recurrence inference

Contract:

- internal
- probabilistic
- revisable
- multi-reading preserving

Latent is never:

- deterministic interpretation
- symbolic certainty
- diagnostic truth system

## 5. Highlights Evolution

Highlights are the primary interaction primitive.

They are:

- user-owned salience anchors
- continuity activators
- reflective navigation anchors
- local-to-global meaning bridges

Runtime influence:

- trigger thread creation/reactivation
- feed glossary candidate generation and motif linkage
- influence opening generation priority
- support reflective resurfacing

Constraint:

- highlights are not AI-owned meaning assertions.

## 6. Glossary Evolution

Glossary is personal continuity memory.

It provides:

- recurrence tracking
- motif preservation
- user-confirmed memory continuity
- contextual resonance support

It is not:

- universal symbol dictionary
- authoritative meaning engine

Core mechanisms:

- candidate vs pinned lifecycle
- suppression / do_not_surface behavior
- contextual resurfacing
- user note ownership

## 7. Reflective Thread Runtime

Threads are reflective continuity trajectories.

Threads are not:

- tasks
- questionnaires
- workflows

Thread runtime includes:

- opening generation and lifecycle
- response continuity
- note layering
- revisit and re-entry
- dormant/reactivated states
- unresolved continuity holding
- non-linear reflective movement

## 8. Reflective Dialogue Philosophy

Dialogue is invitation-based reflective support.

Principles:

- invitations over interrogation
- calm pacing over prompt pressure
- ambiguity preservation over closure
- optionality over coercion
- contextual openings over generic questioning

Key rule:

- AI should know when not to ask.

## 10. Schema and Backend Evolution

Backend direction:

- clean reflective-first schema
- first-class thread/opening/response persistence
- unified highlights target model
- orientation unification
- continuity-aware memory substrate

Transition strategy:

- staged bridges/adapters where runtime compatibility requires it
- controlled compatibility windows
- single-write-owner principle (avoid dual-write chaos)

Why rebuild is preferred:

- legacy schema chain encodes prior workflow-era contracts
- reflective architecture is now structurally different
- clean baseline improves maintainability and reasoning quality
