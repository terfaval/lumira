# Codex Build Plan v1 (Draft)

## Status

Draft — Clean-room Rebuild Execution Plan

This document defines:

- the first clean-room rebuild milestone,
- implementation sequencing,
- scope boundaries,
- stabilization checkpoints,
- and Codex execution philosophy.

This is not:
- a feature roadmap,
- a growth strategy,
- or a production scaling plan.

The goal is:
# building the first stable Lumira organism.

---

# 1. Rebuild Philosophy

The rebuild should optimize for:

- reflective integrity
- continuity correctness
- architectural clarity
- emotional restraint
- and conceptual stability

Not:
- feature count
- AI sophistication
- or rapid expansion.

The first successful rebuild is:
# a small but coherent Lumira.

---

# 2. First Milestone

# Reflective Space Alpha

This is the first true clean-room milestone.

The goal is not:
- advanced cognition,
- or intelligent orchestration.

The goal is:
# a stable reflective continuity substrate.

---

# 3. Reflective Space Alpha Definition

The alpha is successful if a user can:

- create reflective objects
- revisit reflective material
- move across reflective continuity
- connect reflective material over time
- experience continuity without workflow pressure
- maintain reflective context
- and feel psychologically oriented inside the system

The alpha should already feel:
- calm
- breathable
- continuity-aware
- and non-authoritative.

---

# 4. Alpha Scope

The first alpha includes:

## Included

- Reflective Space runtime skeleton
- Reflective Object persistence
- Dream object support
- Basic non-dream object support
- Observation generation
- Minimal glossary memory
- Minimal reflective threads
- Reflective revisitation
- Simple reflective movement
- Calm UI surfaces
- Basic reflective openings
- Minimal latent scaffolding

---

## Explicitly Excluded

The alpha must NOT include:

- graph visualizations
- advanced latent cognition
- autonomous reflective orchestration
- AI insight feeds
- dense dashboards
- gamification
- streak systems
- productivity framing
- completion systems
- multi-agent cognition
- aggressive resurfacing
- complex recommendation engines
- symbolic scoring systems
- automatic deep interpretation
- emotionally pushy AI behavior
- continuity flooding
- “AI knows you” experiences

The alpha must remain:
# restrained.

---

# 5. Build Sequence Philosophy

Build:
# from ontology outward.

Never:
# from UI inward.

Correct build order:

1. canonical domain primitives
2. persistence boundaries
3. runtime skeleton
4. cognition scaffolding
5. reflective assembly
6. UI rendering
7. route delivery
8. refinement

---

# 6. Phase Structure

---

# Phase 1 — Canonical Foundations

Goal:
# establish clean ontology and repo stability

Includes:

- repo initialization
- clean-room folder structure
- domain primitive definitions
- shared type boundaries
- reflective object base models
- persistence contracts
- infrastructure skeleton

No UI polish.
No cognition complexity.

Success condition:
- stable architecture shape
- stable domain vocabulary
- clean ownership boundaries

---

# Phase 2 — Reflective Object Runtime

Goal:
# establish reflective persistence substrate

Includes:

- reflective object CRUD
- dream object support
- simple reflective navigation
- reflective object rendering
- object relationships
- minimal metadata handling

Success condition:
- reflective material exists coherently inside Reflective Space

---

# Phase 3 — Observation Layer

Goal:
# establish descriptive orientation

Includes:

- observation generation
- observation persistence
- observation rendering
- phenomenological structure extraction
- basic orientation views

Observation must remain:
- descriptive
- evidence-linked
- non-authoritative

Success condition:
- reflective material becomes orientable without interpretation collapse

---

# Phase 4 — Glossary Memory

Goal:
# establish continuity memory

Includes:

- glossary term persistence
- reflective object linking
- recurrence handling
- user-defined associations
- contextual glossary surfacing

Success condition:
- continuity begins existing across objects

---

# Phase 5 — Reflective Threads

Goal:
# establish continuity trajectories

Includes:

- thread persistence
- object-thread relationships
- thread revisitation
- thread resurfacing
- dormant thread handling

Threads must remain:
- non-workflow
- non-completion-oriented

Success condition:
- continuity movement exists beyond isolated objects

---

# Phase 6 — Minimal Latent Scaffolding

Goal:
# establish bounded internal cognition

Includes:

- latent snapshot structure
- minimal continuity inference
- basic salience estimation
- reflective opportunity detection

Latent must remain:
- internal
- bounded
- uncertainty-aware

Success condition:
- runtime gains reflective sensitivity without authority escalation

---

# Phase 7 — Reflective Space Assembly

Goal:
# establish living reflective environment

- reflective-space composition

- minimal openings

Success condition:
- the app feels like a reflective space
- not a workflow app

---

# Phase 8 — UI Refinement

Goal:
# stabilize emotional pacing

Includes:

- pacing refinement
- spacing refinement
- visual restraint
- interaction simplification
- cognitive density reduction

Success condition:
- runtime becomes emotionally breathable

---

# 7. Codex Execution Rules

Codex should:

- prefer smaller tickets
- stabilize before expanding
- document architectural decisions
- avoid speculative abstractions
- preserve runtime clarity
- preserve ownership boundaries
- avoid hidden orchestration

Codex should avoid:
- giant refactors
- premature optimization
- universal abstractions
- “smart” architecture patterns
- over-generalization
- hidden coupling

---

# 8. Required Review Checkpoints

Owner review required after:

- Phase 1
- Phase 3
- Phase 5
- Phase 7

Audit recommended after:
- runtime skeleton completion
- thread introduction
- latent introduction

No large expansion should occur without stabilization review.

---

# 9. Cleanup Philosophy

Every major phase should include:

- dead code removal
- naming cleanup
- ownership review
- documentation sync
- coupling review
- architecture simplification

The rebuild should avoid:
# legacy sediment accumulation.

---

# 10. Technical Restraint Principle

The rebuild should always prefer:

- understandable systems
- explicit runtime flow
- stable persistence
- bounded cognition
- emotionally calm behavior

Over:
- intelligence theatrics
- architectural cleverness
- or AI complexity performance.

---

# 11. First True Success Condition

The rebuild is successful when:

a user can enter Reflective Space,
record reflective material,
move across continuity,
revisit evolving meaning,
and feel accompanied without feeling managed.

That is the first real Lumira.

Not intelligence.

Not automation.

Not scale.

---

# 12. Final Build Principle

Build:
# the calmest coherent system first.

Complexity may emerge later.

Reflective integrity must emerge first.
